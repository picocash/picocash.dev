How it works

A mint issues blind-signed bearer tokens against stablecoins held in an on-chain vault. Every token carries a proof anyone can verify without contacting the mint.

01 — MINT

Deposit once

Send stablecoins to the mint's vault with a memo binding the deposit to your quote. The mint blind-signs secrets it never sees — the resulting tokens are yours alone.

02 — PAY

Spend in milliseconds

Services verify tokens offline via DLEQ proofs and settle asynchronously. Credentials are cryptographically bound to each challenge, so interception buys nothing.

03 — MELT

Exit on-chain

Burn tokens, receive stablecoins from the vault. The vault publishes its outstanding supply on-chain — solvency is checked with one eth_call, not trust.

The exit guarantee — every clause on-chain

Withdrawals can never be paused. Each melt pays out exactly once. The fee to exit is capped by the vault's committed ceiling. And raising that cap — like rotating the operator key — takes two days of public notice. Verify it all before depositing a cent.

The project

Everything is open source under Apache-2.0, live on Tempo's Moderato testnet, and under RFC — design feedback is the most valuable contribution right now.

SPECIFICATIONS

pips

The picocash specs — PIP-00 through PIP-05 plus published test vectors. A pip is a seed: small specifications you can grow an implementation from. The open design questions are up for debate in Discussions — start there.

REFERENCE STACK

picocash

Crypto core, mint server, agent SDK, MPP payment method, and a browser wallet demo — TypeScript, tested end to end against the live testnet.

ON-CHAIN CUSTODY

picocash-contracts

The vault and its factory — Solidity, deployed and source-verified on Moderato. Proof of liabilities, publication policy, and the exit guarantee live here.
